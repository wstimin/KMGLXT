# 十夜卡密 · 部署上线说明

> 目标拓扑:Linux 服务器 → (可选 Nginx + HTTPS 证书)→ Node 24 :1111 → SQLite 单文件
> 适用:Debian / Ubuntu / CentOS / RHEL / Rocky
> **推荐方式:一条命令一键安装**,全程交互菜单,日常用 `km` 管理。

## 第 1 章 · 一键安装(推荐)

### 1.1 首次安装

```bash
# 以 root 身份执行(或 sudo)。curl 一次拿到安装脚本,运行后选「1) 安装」:
curl -fsSL https://raw.githubusercontent.com/wstimin/KMGLXT/main/deploy/km.sh -o km.sh
sudo bash km.sh

# 在菜单中选:1) 安装
```

安装向导自动完成:系统依赖 → Node.js 24 → 拉取代码到 `/opt/kmglxt` → 依赖与前端构建
→ 初始化数据库(随机生成管理员密码,只存在本地 `600` 权限文件) → 注册 systemd 服务
`kmglxt` → 放行防火墙 → 注册 `km` 命令。

> **不配置域名也可以正常使用**:访问 `http://服务器IP:1111`,对接方同样用该地址调用 API。
> 安装结束会询问是否添加域名,可跳过,之后随时 `km domain add <域名>`。

### 1.2 验证安装

```bash
km info                     # 查看服务状态/管理员账号密码/域名
curl http://127.0.0.1:1111/api/v1/status   # 应返回 {code:0,...}
```

### 1.3 日常管理

| 操作 | 命令 |
|---|---|
| 调出交互菜单 | `km` |
| 查看当前信息(含账号密码) | `km info` |
| 更新(自动备份数据库、保留现有数据与账号) | `km update` |
| 修改管理员账号/密码 | `km auth` |
| 添加域名并申请 HTTPS 证书 | `km domain add ka.example.com` |
| 删除域名(含证书) | `km domain remove ka.example.com` |
| 更换域名 | `km domain replace` |
| 查看域名列表 | `km domain list` |
| 彻底卸载(删除全部数据,不可恢复) | `km uninstall` |

`km` 支持带子命令直接非交互使用,也可在菜单里逐项操作。

### 1.4 域名与 HTTPS 说明

- 添加域名前请确保该域名 **A 记录已解析到本服务器公网 IP**(证书签发依赖它)。
- 添加域名后自动置 `TRUST_PROXY=1` 并重启服务,`X-Forwarded-For` 生效(IP 白名单用它)。
- 证书由 Let's Encrypt 签发,自动续期(certbot 定时任务);删除/更换域名会一并清理旧证书。
- 不加域名 → TRUST_PROXY=0,来源 IP 直取真实 IP,IP 白名单同样可用。

### 1.5 安装产物位置

| 项 | 位置 |
|---|---|
| 应用代码 | `/opt/kmglxt` |
| 数据库与备份 | `/opt/kmglxt/server/data`(管理的重点) |
| 环境变量 | `/etc/kmglxt/env` |
| 域名登记表 | `/etc/kmglxt/domains` |
| systemd 服务 | `/etc/systemd/system/kmglxt.service` |
| Nginx 反代配置 | `/etc/nginx/conf.d/kmglxt-*.conf` |

## 第 2 章 · 手动部署(可选,高级)

> 以下为不依赖 `km.sh` 的原始流程,与一键安装等价;二选一即可。

### 2.1 初始化

```bash
# Node ≥ 24(NodeSource 或 nvm);上传/克隆代码到 /srv/shiyeka
cd /srv/shiyeka
npm run setup
ADMIN_USER=你的用户名 ADMIN_PASS=你的强密码 npm run init-db
npm run build
```

### 2.2 启动(进程守护二选一)

- systemd(推荐):参考 [`deploy/systemd/kmglxt.service`](systemd/kmglxt.service),把 `@APP_DIR@` 替换为实际路径后放入 `/etc/systemd/system/`,再 `systemctl enable --now kmglxt`。
- pm2:`pm2 start deploy/pm2.config.js && pm2 save`。

### 2.3 Nginx + HTTPS(可选)

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sed "s/your-domain.com/你的域名/g; s/:1111/:1111/g" deploy/nginx.conf \
  | sudo tee /etc/nginx/conf.d/kmglxt.conf >/dev/null
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d 你的域名
```

> 用 Nginx 反代后请改环境变量 `TRUST_PROXY=1`(一键安装由 `km` 自动处理)。

## 第 3 章 · 安全与备份

- **默认无弱口令**:管理员由环境变量或 `km` 生成随机密码初始化;不要用 `admin/123456`。
- 后台账号密码随时可改:`km auth` 或后台侧边栏「修改密码」。
- 常用处可只放行 80/443 到 Web,`1111` 仅内网调用(外部对接用域名经反代)。
- 数据库热备份(不锁库、不用停机):

```bash
cd /srv/shiyeka && node server/scripts/db-backup.js server/data/backups/manual-$(date +%F-%H%M).db
```

- 或后台「系统设置 → 数据与备份」一键备份/下载/恢复。
- 升级前 `km update` 会先在 `server/data/backups/auto/` 留一份更新前快照。

## 第 4 章 · Windows 服务器(仅本地开发用)

- 用「任务计划程序」开机启动 `node server/app.js`(或 pm2-windows-service)。
- `km.sh` 面向 Linux,Windows 请走第 2 章手动流程。
