## 1. 总览:这是什么,谁需要对接

```
买家 ──在外部售卖平台购卡──▶ 拿到卡号
                                  │ 把卡号填进你的站点
                                  ▼
                   你的站点 / 服务(「项目」)
                                  │ POST /api/v1/card/*(带签名)
                                  ▼
                    十夜卡密服务器(全局统一卡池)
                                  │
                                  ▼
                        返回 { code, message, data }
```

- **卡(卡密)统一存在十夜卡密服务器这一个池子里**,你的站点不需要维护自己的卡表。
- **谁需要对接**:需要验卡、激活、扣次、冻结的站点/服务(如付费论坛、会员站、游戏/课程平台)。
- **谁不需要对接**:只负责「卖卡 / 发码」的平台(淘宝、发卡网等)——直接出售卡号即可,不涉及验卡;买家买到的卡最终在需要验卡的站点里激活使用。

### 核心概念「一卡通用 · 单次核销」

- 未使用的卡可以在任意**适用**项目里激活;**激活的那一刻,卡归属该项目**(一张卡一生只成功激活一次)。
- 已归属的卡被**其它**项目调用 → `2006 卡密已绑定其他项目`。
- 套餐可以限制「适用范围」;不在范围内的项目调用 → `2007 该卡在项目不可用`。

### 六接口一览

| 接口 | 路径 | 请求体 | 一句话用途 | 改状态 |
|---|---|---|---|---|
| 健康检查 | `GET /api/v1/status` | - | 连通性探测(无需签名) | 否 |
| 验卡 | `POST /api/v1/card/verify` | `{card}` | 校验有效性 + 剩余,不改状态 | 否 |
| 激活 | `POST /api/v1/card/activate` | `{card}` | 激活并归属本项目,一卡一次 | 是 |
| 扣次 | `POST /api/v1/card/consume` | `{card, times}` | 次数卡按次扣减 | 是 |
| 查询 | `POST /api/v1/card/query` | `{card}` | 返回该卡全部字段(调试用) | 否 |
| 冻结 | `POST /api/v1/card/freeze` | `{card}` | 违规即时冻结(临时停用) | 是 |
| 解冻 | `POST /api/v1/card/unfreeze` | `{card}` | 申诉后恢复 | 是 |

**统一响应**:HTTP 200 + `{ code, message, data }`。业务判断**只看 `code === 0`**,不要按 HTTP 状态码判断(业务错误也是 HTTP 200)。

## 2. 对接三步:从零到上线

> 全程约 1 小时(含自测)。下文示例的服务器地址统一为占位符,请**把占位符换成你的实际服务器地址**(如 `https://card-api.你的域名`,未配域名时 `http://服务器IP或域名:1111`)。

### 步骤 1 · 领取凭证

- 联系十夜卡密管理员,在后台「项目管理 → 新建项目」为你的站点创建项目。
- 领取一组凭证:
  - `app_key`(公开,用于标识你的项目)
  - `app_secret`(私密,**仅展示一次**,务必立即保存)
- `app_secret` 丢失只能找管理员**重置**(旧密钥立即失效),代码要同步更新。
- 项目可配置:
  - `IP 白名单`:把你的服务器**出口 IP**填进去(强烈建议,见第 3 章)
  - `回调地址 callback_url`:需要激活通知时填写(见第 5 章)
  - `限频`:每分钟最大请求数(默认 60,0 = 不限)

### 步骤 2 · 本地自测(10 分钟)

先确认连通性:

```bash
curl http://服务器IP或域名:1111/api/v1/status
```

再用一张真实存在的卡号跑一次验卡(卡号向管理员要,或项目库存中任取一张),完整脚本见 [8.5 附录 A](#85-附录-a--curl-完整自测脚本),期望 `code == 0`。

### 步骤 3 · 选语言实现

已在仓库提供(见 [8.6 附录 B](#86-附录-b--sdk-索引)):

| 语言 | 入口 |
|---|---|
| PHP(7.4+) | `docs/sdk/php/CardApiClient.php`、`example.php` |
| Node.js(18+) | `docs/sdk/node/index.js` |
| Python(3.8+) | `docs/sdk/python/client.py` |
| curl | `docs/sdk/curl/example.sh` |

其余语言(Java / Go / 易语言等)照第 3 章算法实现即可——HTTP + HMAC-SHA256 与语言无关。

### 步骤 4 · 替换对方原有「查卡逻辑」

核心改动:**把「查你自己的数据库」改成「调 API」**。

```php
// 之前:if 卡 in 自己库表 and 状态合法 → 放行(维护两套数据,易不同步)
// 之后:
$res = $api->verify($card);          // 日常入口
if ($res['code'] === 0) {
    /* 放行,展示剩余 */
} else {
    /* 拒绝,提示 $res['message'] */
}
// 开通入口用 activate;按次消耗用 consume($card, 1)
```

### 步骤 5 · 上线检查清单

- [ ] 服务器时间已 NTP 同步(偏差 < 300 秒)
- [ ] 卡号在本地 `trim` + `大写` 后再发送
- [ ] 请求体用实际发送的原始字节(不要重新序列化,见第 3 章)
- [ ] 全链路 HTTPS;`app_secret` 只在服务端
- [ ] 对网络异常做 2~3 次退避重试;成功的请求不要重放
- [ ] 错误码映射成对顾客友好文案(见第 6 章附表)

## 3. 鉴权与签名

除 `GET /api/v1/status` 外,其余接口都必须带以下请求头:

| Header | 说明 |
|---|---|
| `Content-Type` | `application/json` |
| `X-App-Key` | 你的 app_key |
| `X-Timestamp` | 当前 Unix 秒 |
| `X-Nonce` | 本次请求随机串(≤32 位,5 分钟内不可重复使用) |
| `X-Sign` | 签名(十六进制小写) |

### 签名算法

```
bodyHash = sha256( 实际发送的原始请求体字符串 utf8 )
sign     = HMAC_SHA256( app_secret, app_key + "\n" + timestamp + "\n" + nonce + "\n" + bodyHash )
```

### 最容易踩的三个坑

1. **body 必须与实际发出字节完全一致。** `JSON.stringify` 之后不要再做格式化、重排、unicode 转义变化;很多语言对字典/对象重新序列化后字段顺序变化会导致 hash 不一致 → `1001 签名无效`。最稳的做法:先拼好**最终要发送的 JSON 字符串**,对同一字符串算 hash、再原样发送。
2. **卡号服务端会 `trim + 大写` 归一**。你在本地也先做一遍,避免基于原始输入做判断。
3. **nonce 必须随机**。用语言内置 crypto 随机串(如 `random_bytes(16)` 转 hex);同一 nonce 5 分钟内用两次会被判重放。

### 服务端校验顺序(用于排查 1001)

1. `1001 无效的凭证` —— 缺参数 / app_key 不存在
2. `1003 项目已被禁用` —— 项目被管理员停用
3. `1001 时间戳已过期` —— `|now - 发送时间| > 300s`,检查你的服务器时钟
4. `1001 IP 不在项目白名单内` —— 项目配了白名单且来源 IP 不在其中
5. `1001 签名无效` —— hash / hmac / 大小写不正确
6. `1001 请求已重放(nonce 重复)` —— 5 分钟内 nonce 重复使用
7. `1002 接口调用过于频繁` —— 超限频(默认 60/分)

### IP 白名单

- 逗号分隔的精确 IP(如 `1.2.3.4, 5.6.7.8`),留空 = 不限制。
- 判断的是**真实来源 IP**。你的服务端前面若有反向代理,需要置 `TRUST_PROXY=1`(见第 7 章),否则来源 IP 会是代理内网地址、白名单永远不匹配。

### 限频

- 默认每个项目每分钟 60 次,后台可调,0 = 不限;超限返回 `1002`。
- 遇到 `1002` 请退避(延时 1s、2s、4s 重试)。

### 密钥管理

- `app_secret` 泄露 = 项目凭证被拿走。立即找管理员**重置 secret**(新密钥立即生效、旧的作废),并同步更新代码。
- 严禁把 secret 放进前端 JS / 小程序 / App 客户端 / 日志 / 截图。

### 三种语言签名核心(均为 8 行内)

```php
$bodyHash = hash('sha256', $json);                     // $json = 即将发送的字符串
$sign = hash_hmac('sha256',
    $appKey . "\n" . $ts . "\n" . $nonce . "\n" . $bodyHash,
    $appSecret);
```

```js
const bodyHash = crypto.createHash('sha256').update(raw, 'utf8').digest('hex');
const sign = crypto.createHmac('sha256', APP_SECRET)
  .update(`${APP_KEY}\n${ts}\n${nonce}\n${bodyHash}`, 'utf8')
  .digest('hex');
```

```python
body_hash = hashlib.sha256(raw).hexdigest()
sign = hmac.new(APP_SECRET.encode(),
    f"{APP_KEY}\n{ts}\n{nonce}\n{body_hash}".encode(),
    hashlib.sha256).hexdigest()
```

## 4. 六个接口详解与套餐语义

### 卡片状态与冻结

- 状态(枚举):`unused 未使用` / `used 已使用` / `expired 已过期` / `disabled 已禁用` / `void 已作废`。
- 另有独立 `frozen 冻结` 标记:冻结时 verify / activate / consume 返回 `2009 卡已被冻结`。

### 4.1 verify —— 验卡(不改状态)

```
POST /api/v1/card/verify   body: {"card": "SY2026ABCDWXYZ"}
```

成功 `data`:

| 字段 | 类型 | 说明 |
|---|---|---|
| valid | bool | true |
| card | string | 归一化后的卡号 |
| type | string | `duration` / `times` / `permanent` |
| bound_project | int/null | 归属项目 id(未激活为 null) |
| remaining_days | int/null | 时长卡剩余天数(向上取整) |
| remaining_times | int/null | 次数卡剩余次数 |

典型失败:`2009` 冻结 / `2006` 绑定他项目 / `2007` 项目不可用 / `2003` 过期 / `2004` 禁用 / `2005` 作废。

**推荐时机**:每次登录、每次访问付费内容——只判断 `code == 0` 与剩余值,不改状态。

### 4.2 activate —— 激活绑定(一卡一生一次)

```
POST /api/v1/card/activate body: {"card": "..."}
```

- **原子**:数据库条件更新,并发抢同一张卡只有一方成功,另一方 `2002 卡密已被使用`。
- 成功 `data`:`{ type, card, expire_at, remaining_times, project_id }`
  - `expire_at`:时长卡 = 激活时刻 + 套餐天数(unix 秒);次数/永久卡为 `null`
  - `remaining_times`:次数卡剩余(开通后未扣 = 套餐次数)
  - `project_id`:本项目 id(归属即写入)
- **激活即归属本项目**;之后再被其它项目调用将 `2006`。
- 成功后若项目配置了回调地址,会异步 POST 通知(见第 5 章)。

**推荐时机**:开通类入口(注册、买课、升级、充值生效)。典型失败如 `2002` 已被使用、`2006`、`2007`、`2009`、`2004`、`2005`、`2003`。

### 4.3 consume —— 次数扣减(仅次数卡)

```
POST /api/v1/card/consume body: {"card": "...", "times": 1}
```

- 前提:卡**已激活**;未激活 → `2010 卡密尚未激活`。
- 非次数卡扣次 → `2011 该套餐不支持扣次数`。
- 请求次数 > 剩余 → `2008 次数不足`。
- **扣到 0 自动转为 `expired`**。
- 成功 `data`:`{ card, consumed, remaining_times }`。

### 4.4 query —— 全字段查询

```
POST /api/v1/card/query body: {"card": "..."}
```

成功 `data`:`{ card, status, frozen, type_id, kind, bound_project: {id, name} | null, activated_at, expire_at, times_used, remaining_days | remaining_times }`。

**特例**:query 不校验适用范围、也不因冻结拒绝,但同样做归属隔离(`2006`)。适合查单卡明细与对账;线上高频场景请用 verify。

### 4.5 freeze / unfreeze —— 冻结与解冻

```
POST /api/v1/card/freeze   body: {"card": "..."}   → data: {card, status: "frozen"}
POST /api/v1/card/unfreeze body: {"card": "..."}   → data: {card, status: "normal"}
```

- 置 / 清除冻结标记;**对已过期、已禁用的卡也可以冻结**,冻结不影响后台状态枚举。
- 主力场景:违规处置(即时停用)、申诉解冻。
- 注意 `2006`:只能操作自己项目里已归属的卡。

### 套餐语义

| 套餐 kind | 有效期计算 | verify / query 返回 | 过期判定 |
|---|---|---|---|
| `duration` 时长卡 | `expire_at = 激活时刻 + days×86400` | `remaining_days`(向上取整) | 到期 → `2003`,自动落为已过期 |
| `times` 次数卡 | 无自然期限 | `remaining_times = times - times_used` | 扣到 0 → 自动转已过期 |
| `permanent` 永久卡 | 永不过期 | 一律 `null` | 无 |

### 一卡通用细则

- 未使用卡可在**任意适用项目**里激活(全池共享)。
- 激活即归属;已归属卡对其它项目全部接口返回 `2006`。
- 套餐可配「适用范围」(项目 id 列表,`[]` = 全部项目);不适用 → `2007`。

## 5. 激活回调(可选)

- **触发条件**:`activate` 成功 **且** 项目已配置 `callback_url`。
- **请求**:`POST callback_url`,`Content-Type: application/json`,无鉴权头。
- **payload**:

| 字段 | 类型 | 说明 |
|---|---|---|
| card | string | 卡号 |
| project_id | int | 本项目 id |
| project_name | string | 项目名称 |
| type | string | 套餐类型 |
| expire_at | int/null | 时长卡激活后的过期 unix 秒,否则 null |

- **可靠性**:最多重试 3 次(第 1 次失败等 1 秒、再等 2 秒),单次超时 10 秒;fire-and-forget(不阻塞 activate 响应)。回调地址请用响应快、不易超时的 HTTPS 接口。
- **接收端建议**:
  - 以 `card` 为幂等键(回调可能重复到达,穿透到业务层会重复处理)。
  - **当前回调不携带签名**,不要在回调里执行高敏感/不可逆动作(如直接发货、直接扣款);如需要强校验,可对回调来源服务器的出口 IP 做白名单,或等后续回调签名扩展。

## 6. 常见业务场景落地

### 场景 A · 开通(注册 / 买课 / 升级)

```
res = activate(card)
if res.code == 0:
    按 res.data.type 处理:
      duration   → 记录 expire_at
      times      → 记录 remaining_times
      permanent  → 无期限
else:
    2002 「该卡已被使用」;2007 「该卡不适用本项目」;2009 「该卡已被冻结」...
```

> 不要用 verify 代替激活入口:verify 不改状态,同一张卡会被反复「开通成功」。

### 场景 B · 日常访问鉴权

```
res = verify(card)
if res.code == 0 且剩余值 > 0:
    放行
else:
    拒绝并提示 res.message
```

### 场景 C · 次数池扣减

```
res = consume(card, 1)
if res.code == 0: 放行本次
else: 2010 未激活 / 2008 次数不足 / 2003 已过期 / 2009 冻结 ...
```

### 场景 D · 违规处置

```
freeze(card)    # 即时停用
unfreeze(card)  # 申诉解冻
```

只能处置**本项目已归属**的卡(否则 `2006`)。

### 场景 E · 过期 / 作废

前台按 `code` 提示对应文案(见下表)并引导购买新卡。

### 成功判定

**判定标准只有 `code === 0`**。业务失败时 HTTP 仍是 200,`message` 可直接透出。

### 错误码 → 对顾客文案建议

| code | message | 对顾客文案建议 |
|---|---|---|
| 2001 | 卡号不存在 | 卡号不存在,请核对后重试 |
| 2002 | 卡密已被使用 | 该卡已被使用,请联系卖家 |
| 2003 | 卡密已过期 | 卡密已过期,请购买新卡 |
| 2004 | 卡密已被禁用 | 该卡已被禁用,如有疑问请联系客服 |
| 2005 | 卡密已作废 | 该卡已作废 |
| 2006 | 卡密已绑定其他项目 | 该卡不适用于当前服务 |
| 2007 | 该卡在项目不可用 | 该卡不适用于当前服务 |
| 2008 | 次数不足 | 剩余次数不足 |
| 2009 | 卡已被冻结 | 该卡已被冻结,请联系客服 |
| 2010 | 卡密尚未激活 | 请先激活 |
| 2011 | 该套餐不支持扣次数 | 该套餐不支持扣次 |

### PHP 完整示例(复用仓库 SDK,约 30 行)

```php
<?php
require __DIR__ . '/CardApiClient.php';

// 服务器地址 + 后台领取的凭证
$API = new CardApiClient('https://card-api.你的域名', $appKey, $appSecret);

$card = strtoupper(trim($_POST['card'] ?? ''));
if (!$card) exit(json_encode(['code' => 400, 'msg' => '请输入卡号']));

// 开通入口 → activate(首次激活归属本项目)
$res = $API->activate($card);
if ($res['code'] === 0) {
    exit(json_encode(['code' => 0, 'msg' => '开通成功', 'data' => $res['data']]));
}
// 日常入口 → verify;按次消耗 → consume($card, 1)
// 统一按 code 判断,不是 HTTP 状态码
exit(json_encode(['code' => $res['code'], 'msg' => $res['message'], 'data' => null]));
```

## 7. 安全与部署建议

> 本系统运行在服务器上,对接方只需要知道服务器地址;部署侧的注意事项交管理员,这里列的是**影响对接成败**的部分。

- **HTTPS 必须**:建议服务器前面放反向代理(Nginx / Caddy)终结 TLS。你的请求应用 `https://...` 地址。
- **TRUST_PROXY 的取舍**:服务端设 `TRUST_PROXY=1` 后,`req.ip` 才取自 `X-Forwarded-For`(IP 白名单依赖它)。设置前确保该头**只可能来自你自己的代理**,否则外部可伪造来源 IP 绕过白名单。设置后把真实出口 IP 配进白名单。
- **secret 边界**:`app_secret` 只能存在于对接方服务器;浏览器、小程序、App 客户端一律不能持有。
- **超时与重试**:网络错误建议退避重试 2~3 次;**成功的请求不要重放**(接口按语义幂等,重放会导致重复扣次、或激活报 `2002`)。
- **限频与风控**:默认 60/分;出现异常尖峰(被刷)时管理员可在后台调低,并在「核销流水」里审计。
- **服务端环境变量**(交给管理员):`PORT`(默认 1111)、`DATA_DIR`(数据库目录)、`TRUST_PROXY`、`ADMIN_USER` / `ADMIN_PASS`(仅首次初始化超管,**无默认弱口令**)。
- **扩展提醒**:内存限频为单进程粒度,多实例部署需自行外置;备份走后台「数据与备份」。

## 8. 旧卡迁移 / 常见问题 / 附录

### 8.1 对方已有自己的卡表?导入即可

由管理员在后台「导入」,txt 文本、每行一条:

```
卡号
卡号,状态
卡号,状态,备注
```

- 分隔符:逗号 / Tab / 分号;状态支持中文或英文(`未使用` / `已使用` / `已过期` / `已禁用` / `已作废`)。
- 卡号自动 `大写 + 去空格`,需 4~40 位字母数字;重复卡自动跳过;文件 ≤ 5MB。
- 导入后,对方站点把验卡代码整体替换为 API 调用,即与全局池共用同一批卡。

### 8.2 校验位(可选,后台生成卡时勾选)

- 开启后卡号**末位为校验字符**,对接方可以先用公式本地预校验,把明显瞎猜的卡挡在请求之外。
- 默认字符集:`23456789ABCDEFGHJKLMNPQRSTUVWXYZ`(剔除 `0O1lI`);默认总长度 16(不含自定义前缀,勾选校验位时其中末 1 位为校验字符)。
- 算法:`sum = Σ( len(c)内 index(c[i]) + 1 + i×7 )`,`校验字符 = charset[sum % len(charset)]`。
- 注意:本地预校验对**除末位外**的前缀计算;字符集在后台自定义时算法随字符集变化。
- 服务端会先 `trim + 大写`,本地校验前也先大写。

### 8.3 错误码速查表

| code | message | 触发场景 |
|---|---|---|
| 0 | ok | 成功 |
| 1001 | 签名无效 / 时间戳已过期 / 请求已重放 / IP 不在白名单 | 鉴权失败(细分见第 3 章) |
| 1002 | 接口调用过于频繁 | 触发项目限频 |
| 1003 | 项目已被禁用 | 管理员停用了该项目 |
| 2001 | 卡号不存在 | 查无此卡 |
| 2002 | 卡密已被使用 | 激活遇已使用;并发抢先激活 |
| 2003 | 卡密已过期 | 时长到期 / 次数耗尽 |
| 2004 | 卡密已被禁用 | 后台禁用 |
| 2005 | 卡密已作废 | 后台作废 |
| 2006 | 卡密已绑定其他项目 | 一卡单次核销的隔离 |
| 2007 | 该卡在项目不可用 | 套餐适用范围不含本项目 |
| 2008 | 次数不足 | consume 请求次数 > 剩余 |
| 2009 | 卡已被冻结 | 对方项目调 freeze 后 |
| 2010 | 卡密尚未激活 | consume 一张未激活的卡 |
| 2011 | 该套餐不支持扣次数 | consume 时长卡 / 永久卡 |

### 8.4 FAQ

1. **我的卡想放到别的平台卖,要不要对接?** 卖卡平台只负责发卡号,**不需要对接**;买家最终在哪个需要验卡的站点用,由那个站点拿凭证接 API。
2. **一张卡能多处通用吗?** 「一卡单次核销」下不行:卡在哪个项目激活就归属哪个项目,其它项目一律 `2006`。想让一张卡全平台可用,就不设适用范围,但仍由**第一个激活它的项目**持有归属。
3. **卡被别的项目先激活了怎么办?** 那个项目就是归属者,本项目不能再激活(`2006`)。核对卡号来源或联系管理员。
4. **对方没有技术能力,怎么对接?** 可以通过后台的卡明细查询/导出做人工验卡;或由对方的平台方提供现成的对接模板给技术方照抄(本手册的 PHP / Node / Python 示例即可)。
5. **反复报 1001?** 按第 3 章顺序查:① 时钟同步(时间戳已过期)→ ② IP 白名单是否匹配(反向代理要 TRUST_PROXY)→ ③ body 是否重新序列化(签名无效)→ ④ nonce 是否被重复使用。
6. **接口返回 HTTP 200 却是错误码?** 正常现象——业务错误码都在 `code` 字段里,按 `code` 判断。
7. **回调收不到?** 确认 `callback_url` 公网可达、HTTPS、返回 2xx、响应快;回调最多重试 3 次(退避 1s / 2s)。
8. **想把对方已经卖出去的旧卡接进来?** 按 8.1 导入(可带「已使用」状态),导入后替换对方验卡代码即可。

### 8.5 附录 A · curl 完整自测脚本

```bash
#!/usr/bin/env bash
# 把 BASE / APP_KEY / APP_SECRET 换成真实值;CARD 用一张真实存在的卡
BASE='https://card-api.你的域名'        # 换成实际服务器地址
APP_KEY='XXXXXXXXXXXXXXXXXXXXXXXX'               # 24 位
APP_SECRET='XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'  # 48 位
CARD='SY2026XXXXXXXX'

body="{\"card\":\"$CARD\"}"
ts=$(date +%s)
nonce=$(head -c 16 /dev/urandom | od -An -tx1 | tr -d ' \n')
body_hash=$(printf '%s' "$body" | openssl dgst -sha256 | awk '{print $2}')
sign=$(printf '%s\n%s\n%s\n%s' "$APP_KEY" "$ts" "$nonce" "$body_hash" \
  | openssl dgst -sha256 -hmac "$APP_SECRET" | awk '{print $2}')

curl -sS -X POST "$BASE/api/v1/card/verify" \
  -H 'Content-Type: application/json' \
  -H "X-App-Key: $APP_KEY" \
  -H "X-Timestamp: $ts" \
  -H "X-Nonce: $nonce" \
  -H "X-Sign: $sign" \
  -d "$body"
echo
```
